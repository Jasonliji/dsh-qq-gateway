# QQ 多账号网关

一套工具接管多个 QQ 号。每个号连自己的 OneBot 11 后端，收到的消息按账号路由进指定的 DSH 会话，发送、读消息、改资料共用同一组工具——不再为每个号镜像一份。

## 要解决的事

以前每个号配一套 MCP server，于是会话里出现两整套一模一样的 `qq_*` 工具，每轮都在为重复 schema 付 token；而且「谁的桥服务谁」只能靠人记。

这里换成一个 host 插件：账号是一张表，工具只有一套，用 `account` 参数分人。

## 前置

- 每个 QQ 号要有一个 OneBot 11 后端（SnowLuma、NapCat 等），各占一组端口。同一个后端进程可以承载多个号，一个号一份配置。
- **收消息靠 WebSocket**，所以后端要开 WS 口（例：HTTP 3010 / WS 3011）。只填 HTTP 只能发不能收。
- 装完要重启 DSH。插件跟宿主同进程，改完不重启等于没改。

## 配置

在 **设置 → 插件** 里给 `qq-gateway` 填 `accounts`，一项一个号：

```yaml
accounts:
  - id: hua
    httpUrl: http://127.0.0.1:3010
    wsUrl: ws://127.0.0.1:3011
    accessToken: ''
    session: session-xxxxxxxx-…
    owner: '100000000'
    allow:
      private: ['100000000']
      groups: ['100000001']
  - id: yu
    httpUrl: http://127.0.0.1:3020
    wsUrl: ws://127.0.0.1:3021
    session: session-另一个
    owner: '另一个主人号'
    allow:
      private: [...]
      groups: [...]
```

- `session` 带不带 `session-` 前缀都认。**留空就只发不收**——宁可不动，也不往猜的会话里塞东西。
- `allow` 是白名单，**空数组是「谁都不理」**，不是全放。
- `owner` 是这个号上哪个 QQ 说的话算指令。投递时每条都标［主人］或［外人］，上层据此分开处置；留空则全部当外人。

## 调参（顶层，不是账号级）

| 项 | 默认 | 干什么 |
|---|---|---|
| `contextMaxCount` | 20 | 被叫起来时最多带前几条攒下的消息 |
| `contextMaxChars` | 6000 | 同上，按字符卡。攒一天的闲聊不能一股脑塞进去 |
| `batchQuietSec` | 15 | 群里安静多少秒才把攒下的几条一起投一次。调小反应快但回合多、费 token |
| `criticalQuietSec` | 1.2 | 私聊、@ 到你、引用你那条的静默窗。问话不能慢慢攒 |
| `batchMaxWaitSec` | 600 | 一直热闹时最多攒多久必须投一次 |
| `followupTimeoutSec` | 300 | 投出去后等会话接住的上限，超时判这条没投进去 |
| `maxQueueAgeSec` | 300 | 从进队到真正投递的上限，超过就丢（私聊和 @ 到的不丢） |
| `probeIntervalSec` | 120 | 多久探一次登录态，写进 `qq_status`。0 就不探 |
| `stateFile` | 空 | 状态落盘位置，留空放 DSH 家目录下 |
| `label` | 空 | 唤醒头前缀，新旧两套同时挂着时用来分辨是谁投的 |

## 工具

| 工具 | 干什么 |
|---|---|
| `qq_status` | 每个号连没连上、登录的是谁、路由到哪、最近一次投递成不成 |
| `qq_send` | 发消息，可带 `atUserId` 点名、`replyToMessageId` 引用 |
| `qq_read` | 读会话，默认只给没读过的，每行带消息 id |
| `qq_mark_read` | 推进已读水位，只往前不往后。`throughSeq` 必须给——省略不是「全标已读」，是不动 |
| `qq_profile` | 改自己这个号的昵称和签名 |
| `qq_lookup` | 查群列表、群成员、好友 |
| `qq_poke` | 拍一拍，群里要指定拍谁 |

## 投递的规矩

- **群里默认不唤醒**：`groupWakeMode: mention`（默认）时，群里闲聊只记账不投；只有被点名、被 @全体、被拍、被引用、私聊才投一次。投的时候把上次投递之后攒下的全部消息一起带过去当上下文——不吵，但被叫起来时前因都在。设成 `all` 回到「来一条投一条」。
- **攒批**：有人说话就重置计时，群里安静够久（默认 15 秒）才把攒下的几条一起投一次。十条消息只起一个回合，不是十个。一直热闹也有上限（默认 10 分钟），到点必投。私聊、@ 到你、引用你那条用短的静默窗（默认 1.2 秒），问话不攒。
- 同一个会话同一时刻只投一条，后面的排队，不并发堆上去。
- 等会话接住有上限、在队里等也有上限，两个都可配，默认五分钟。
- **私聊、群里的 @、@全体、引用我那条、拍一拍**都算不可丢：过期也照投，晚到比不投强。
- 群里没点我名的闲聊才允许过期丢，不把旧话翻出来。
- 后端断了、连了回来，都会往会话投一条系统消息，按账号一分钟节流。

## 已知限制

- **一个号一个 QQ 客户端实例，这块省不掉。** 现存能跑的 OneBot 11 实现都挂在真客户端上；纯协议那条路（go-cqhttp 配签名服务）2023 年就断了，剩下要签名的命脉在别人手里，风控也更吃亏。两个号约 1.7G，三个号往上加。
- 只认 OneBot 11。要换别的协议（比如 Lagrange 的 Milky），得加一层适配。
- 会话 id 是写死的映射。换会话要改配置。
- 单条正文限三千字，超了直接拦下报错，不会悄悄失败。

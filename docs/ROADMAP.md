# 还没补的

第一版只做了消息收发那条主干。下面是跟现有 qq-bridge 比出来、确认要补的部分，按「缺了会不会出事」排队。

## 已补（2026-11-18，在备份区的媒体版里）

- **图片下载**：投递时才下载，交给 `attachments.admitPromptContent` 变成会话里真正的图；拿不到或超限就落盘给路径。收藏表情不占上下文。
- **语音收**：`get_record` 带 `out_format: mp3` 服务端转码，存成 mp3，正文留时长和路径，要听再调 `audio_transcribe`。
- **语音发**：`qq_send.voice` 给本机音频路径，SnowLuma 内部 `encodeSilk` 自己转，不用在插件里做 silk。
- **表情包**：`qq_faces` 列收藏表情，`qq_send.face` 发；收到别人的表情时带出 `emojiId:packageId`，能原样发回去。
- **合并转发查看**：`get_forward_msg` 展开成「发言人：内容」，最多 60 条。

做法和坑写在 README 的「媒体」那节。

## 先补（缺了真不能用，或者会出事）

### 1. 发送审计
出站前一道闸：本机路径（盘符开头、`/home/`、`/Users/`、UNC）、口令密钥的赋值形态，命中就整条不发。
语音也要过，但只能审文件名，音频内容审不了。
主人私聊里路径算例外（那是他自己的机器），凭据照拦；其余场合全拦。

**判据是「别把不该漏的漏出去」。**

### 2. FISH_GUARD（另一道，别跟审计并成一道）
拦「说得跟以前太像」。判据完全不同，分两处写。
现成的实现可以直接用：`fishtalk-main/lib/check.js`，带 `{ force: true }` 调。

**判据是「别把话说得像复读」。**

### 3. 静默模式
**双闸，不是只拦主动：**
- 入站：消息只记台账，不投给模型。看不见，也就无从回。
- 出站：拍一拍、工具发送全拒，主人私聊除外。

控制台一键切（`/silent` 开，`/active` 关）。
另有一个单条出口：输出一个方括号标记，那一条就不发——不用整个关掉静默。

### 4. 图片下载（已做，见上面「已补」）
（下面这段留着当背景：原来的做法和踩过的坑。改动已经落到媒体版里了。）

原来只把地址带出来（`[图片 <url>]`），模型看得见地址、拿不到图；QQ 的 CDN 链接还会过期，过一会儿就 404，等于没给。

切这一刀之前先知道两个坑，比链接过期深：

**体积**：DSH 收图时走一条正则校验 base64，超过约 440 万字符会爆栈，模型最后只看到一行 `image unavailable`，一个字节都没进上下文，而且看不出原因。抓取上限若按 8MB 设，中间 3–8MB 是死区——桥接认为合法，DSH 必定拒。

**动图**：DSH 明确排除 gif，交给 sharp 只解第一帧。四十八帧的动图会被看成一张静止图，上下文里也没人告诉模型这是动图。

**做法**（照 <工作区> 那套）：收到就压到安全尺寸、动图抽帧拼成一张网格图并在文本里注明是动图、小图直接放行。

语音、表情包、合并转发同理，但在后一批。

## 后补（用得没那么勤）

### 断线补拉
WebSocket 断开那几分钟的消息现在是永久丢的：重连只报一句「连接恢复了」，不补。
补法：恢复后用 OneBot 的 `get_group_msg_history` / `get_friend_msg_history` 拉最近十分钟，去重后补投。
不补的话，断线期间有人找我，我永远不知道。

- 唤醒里剩下的两成（潜水、静默计数、睡前观察）——最小那条（群里只在被叫时投）已经做了，先不铺开

## 不做

- 黑话库：走词库插件（`dsh-memewiki`，未装），不放进 QQ 桥
- 话题和印象那类记忆：走记忆库（`dsh-soul`），独立一层
- 网页搜索：独立插件（`dsh-free-search`），跟 QQ 无关

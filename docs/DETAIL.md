# QQ 多账号网关

## 它做什么

把多个 QQ 号接进 DSH，每个号的消息落进各自的会话，而会话里只有一套 QQ 工具。

- **收**：连每个号后端的 WebSocket。事件分四条支路——聊天消息、请求（好友申请、群邀请）、通知（拍一拍）、元事件（心跳直接忽略）。聊天消息先过白名单，再去重、记序号，按账号映射投进对应的 DSH 会话；同一会话短窗口内的几条并成一次唤醒。
- **发**：`qq_send` 一个工具服务所有号，`account` 选是谁在说，支持多条、@ 和引用回复。
- **读**：`qq_read` 读会话（默认只给没读过的，每行带消息 id），`qq_mark_read` 推进已读水位。
- **拍**：`qq_poke` 拍出去；被拍进来也会投一条。
- **资料**：`qq_profile` 改这个号自己的昵称和个性签名。
- **查**：`qq_lookup` 读群列表、群成员、好友，@ 谁的时候用来拿号。

## 为什么不做成每号一份 MCP

每号一份 MCP server，会话里就会出现整套重复的工具定义，每轮都在为重复 schema 付 token；PTC 模式下每个工具签名还要渲染两遍（参数表一遍、输出表一遍），倍数再翻一番。改成 host 插件后，账号是一张表，工具是一套。

## 用法

1. 给每个 QQ 号准备好 OneBot 11 后端，HTTP 和 WS 各一组端口。
2. 在插件设置里填 `accounts`：`id`、`httpUrl`、`wsUrl`、`accessToken`、`session`、`owner`、`allow`。
3. 重载或重启 DSH，用 `qq_status` 确认每个号都在线、会话都对上了。
4. 让对方向这个号发一句，看消息有没有落进会话；再让会话回一句，看对方收不收到。

## 投递的期限与排队

- 同一个会话同一时刻只投一条：前一条没回来，后一条压着，不并发。
- 两个期限都按「入队 → 接住」整条链算，不只包住那一次调用：等会话接住的上限、在队里等轮到的上限，各默认五分钟，可配。
- 私聊、@、@全体、引用我那条、拍一拍、好友申请都算不可丢，过期也照投；群里没点我名的闲聊才丢。
- 被拍、被引用、被 @ 都会在唤醒头里标出来；每条消息带消息 id，引用回复才够得着。
- 后端断线、恢复、重连失败会投系统消息，按账号一分钟节流，重连不刷屏。

## 必须知道的限制

- **一个号一个 QQ 客户端实例，内存这块省不掉。** 现存能跑的 OneBot 11 实现都挂在真客户端；纯协议的 go-cqhttp 路线 2023 年随腾讯改协议加签名而中断，其余免签名的实现同样受制于签名服务，风控上也更容易被识别。用省内存去赌老号不划算。
- **只有 WebSocket 能收消息。** 只配 `httpUrl` 时这个号只能发不能收。
- **白名单空数组 = 谁都不理。** 这是有意的：默认闭嘴比默认全放安全。好友申请和群邀请不走白名单，否则陌生人永远进不来也永远看不到。
- **会话映射是写死的。** 换会话要改配置，不做「猜最近活跃会话」那种兜底——推错人比不推糟得多。
- 投消息用的是 `agent.followup`，消息必须是对象（`{ id, role, content, source }`）。塞字符串会写坏会话日志，重启后那个会话打不开。
- 单条正文限三千字，超了直接报错。
